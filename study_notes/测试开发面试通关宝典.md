**软件测试的核心原则（贯穿全篇）**
1. 测试证明缺陷存在，不能证明缺陷不存在。
2. 穷尽测试不可能，需基于风险取舍。
3. 缺陷具有集群性（80% 缺陷集中在 20% 模块）。
4. 测试应尽早介入（需求阶段就开始）。
5. 杀虫剂悖论：同样用例反复跑会失效，需持续更新。
6. 测试依赖于上下文（不同软件测试策略不同）。

## 一、测试基础

**1. 软件测试的目的是什么？**
软件测试通过运行或评审软件来发现缺陷、验证软件是否满足需求、评估软件质量，从而降低发布风险、为上线决策提供依据。核心认知：测试只能证明缺陷存在，无法证明软件完全无缺陷，因此测试的价值在于用有限成本尽可能多地暴露高风险问题。
**【一句话总结】** 测试是用有限成本尽早发现缺陷、评估质量、降低上线风险，而非证明软件没有 Bug。

**2. 黑盒、白盒、灰盒测试的区别？**
- 黑盒：不关注内部实现，把系统当"黑箱"，只基于需求和输入输出设计用例（等价类、边界值等），关注功能是否正确。
- 白盒：基于代码内部逻辑结构设计用例（语句、判定、条件、路径覆盖），关注代码是否被正确执行。
- 灰盒：介于两者之间，既了解部分内部结构（如接口、数据库），又从功能角度设计用例，接口测试就是典型灰盒。
**【一句话总结】** 黑盒看功能不看代码，白盒看代码逻辑覆盖，灰盒结合内部结构与功能，接口测试属灰盒。

**3. 常用的黑盒测试用例设计方法？**
- 等价类划分：把输入划分为有效/无效等价类，每类取代表值，减少用例数量。
- 边界值分析：取边界及边界上下值（最易出错），常与等价类配合。
- 判定表：多条件组合逻辑用判定表理清所有组合。
- 因果图：分析输入条件与输出的因果关系。
- 正交实验法：多参数多取值时用正交表科学减少组合。
- 场景法：按业务流程的基本流和备选流设计。
- 错误推测法：凭经验推测易错点。
**【一句话总结】** 主用等价类+边界值，多条件用判定表/因果图，多参数用正交法，流程用场景法，辅以错误推测。

**4. 白盒测试的逻辑覆盖有哪些？（由弱到强）**
语句覆盖 < 判定覆盖 < 条件覆盖 < 判定/条件覆盖 < 条件组合覆盖 < 路径覆盖。
- 语句覆盖：每条语句至少执行一次（最弱）。
- 判定覆盖：每个判定的真假都取到。
- 条件覆盖：每个条件的真假都取到。
- 条件组合覆盖：每个判定内条件的所有组合都取到（较强）。
- 路径覆盖：覆盖所有可能执行路径（最强，成本最高）。
**【一句话总结】** 覆盖强度由弱到强：语句→判定→条件→判定条件→条件组合→路径，越强越全但成本越高。

**5. 描述一个完整的测试流程。**
需求分析（理解并评审需求，明确测试范围）→ 制定测试计划（人力、时间、范围、风险）→ 设计测试用例 → 用例评审 → 搭建测试环境、准备数据 → 执行测试 → 提交并跟踪缺陷 → 回归测试 → 输出测试报告 → 参与上线验证与线上监控。
**【一句话总结】** 需求分析→测试计划→用例设计评审→环境准备→执行→缺陷跟踪→回归→报告→上线验证，全流程闭环。

**6. 一个 Bug 的生命周期？**
New（新建）→ Assigned（指派给开发）→ Open/处理中 → Fixed（已修复）→ 测试回归验证 → Closed（关闭）。
异常分支：验证未通过则 Reopen（重新打开）；开发认为非缺陷或无法复现可 Rejected；暂不修复可标记 Deferred（延期）。
**【一句话总结】** Bug 从新建、指派、修复、验证到关闭，验证不过则 Reopen，非缺陷则 Rejected。

**7. 缺陷等级怎么划分？**
- 致命(Blocker)：系统崩溃、核心主流程不可用、数据丢失、安全漏洞。
- 严重(Critical)：主要功能失效，但有临时规避方案。
- 一般(Major)：次要功能问题，不影响主流程。
- 轻微(Minor)：界面、文案、体验类小问题。
**【一句话总结】** 按影响程度分致命、严重、一般、轻微四级，主流程不可用是致命，界面小问题是轻微。

**8. 优先级(Priority)和严重程度(Severity)的区别？**
- 严重程度：缺陷对系统功能的破坏程度，偏客观、由测试判定。
- 优先级：缺陷修复的紧急先后顺序，偏主观、结合业务价值判定。
两者不一定一致：例如"首页公司名写错"，功能上严重程度低，但对品牌影响大、优先级高；反之某个隐蔽的崩溃严重程度高但用户几乎触发不到，优先级可能不高。
**【一句话总结】** 严重程度看破坏大小（客观），优先级看修复紧急度（结合业务），二者可能不一致。

**9. 一个高质量的缺陷报告应包含哪些内容？**
标题（简洁准确，一句话点明问题）、缺陷ID、所属模块、测试环境（系统/浏览器/版本/账号）、前置条件、详细复现步骤、预期结果、实际结果、严重程度与优先级、附件（截图/日志/录屏）、指派人、发现版本。核心是让开发能快速复现和定位。
**【一句话总结】** 好的缺陷报告要能让开发一键复现：清晰标题、环境、复现步骤、预期与实际结果、截图日志缺一不可。

**10. 开发说"这不是 Bug"怎么办？**
先自查：对照需求文档/PRD/原型，确认是否与需求不符——若不符则是 Bug，拿出依据。若需求本身未定义（模糊地带），不与开发争论，拉上产品经理三方确认，由产品拍板是否修改。全程用复现步骤、日志、截图等客观证据沟通，对事不对人。
**【一句话总结】** 先对照需求判定，有依据就据理力争，需求模糊则拉产品三方确认，用证据沟通不争吵。

**11. 冒烟测试、回归测试、系统测试的区别？**
- 冒烟测试：新版本提测后，先快速验证核心主流程是否通畅，不通则打回，避免浪费详细测试时间。
- 回归测试：代码修改（修复 Bug 或新增功能）后，验证原有功能未被破坏，常自动化。
- 系统测试：对整个系统进行完整的功能与非功能（性能、安全、兼容）测试。
**【一句话总结】** 冒烟是提测门槛快速验主流程，回归是改动后验老功能没坏，系统测试是全面完整测试。

**12. α测试和β测试的区别？**
- α测试：在开发方受控环境下，由内部用户或测试人员进行的验收前测试。
- β测试：软件交给真实用户在真实环境中使用测试，开发方不可控，收集反馈用于改进（如公测）。
**【一句话总结】** α测试是内部受控环境测，β测试是真实用户真实环境公测，α在前β在后。

## 二、功能测试

**13. 如何测试一个登录功能？（万能框架题）**
从多维度覆盖：
- 功能正常：正确账号密码登录成功、跳转正确。
- 功能异常：错误密码、账号不存在、空账号、空密码的对应提示。
- 边界/特殊：账号密码超长超短、特殊字符、SQL注入、XSS、前后空格。
- 安全：密码密文显示与加密传输、连续失败锁定、验证码防爆破、Session/Token 有效期与退出失效。
- 会话：记住密码、多端登录、Token 过期。
- 兼容与UI：多浏览器、分辨率、布局与提示文案。
**【一句话总结】** 从正常、异常、边界、安全、会话、兼容六个维度覆盖，重点是安全（加密、锁定、注入）。

**14. 如何测试一个搜索框？**
- 功能：精确/模糊搜索、结果准确性、排序、无结果提示、分页。
- 边界特殊：空输入、纯空格、超长、特殊字符、SQL注入、Emoji、大小写、中英文繁简。
- 交互：回车与点击触发、搜索历史、联想提示、清空按钮。
- 性能：大数据量响应时间、高并发。
**【一句话总结】** 覆盖精确模糊搜索准确性、空值超长特殊字符边界、交互体验和大数据量性能。

**15. 如何测试文件上传功能？**
- 类型：允许类型能传、禁止类型被拦、无后缀、伪造后缀（改扩展名）。
- 大小：0字节、正常、超上限、临界值。
- 数量：单个、批量、超数量限制。
- 异常：上传中断网、重复上传、同名文件、中文/特殊字符文件名。
- 安全（重点）：上传木马/可执行文件、路径穿越、文件内容与后缀不符、上传目录执行权限。
- 交互：进度条、取消、失败重试、成功提示。
**【一句话总结】** 从类型、大小、数量、异常、安全、交互六方面测，安全上传木马和伪造后缀是重点。

**16. 如何测试支付功能？**
- 正常：各支付方式（微信/支付宝/银行卡）成功。
- 金额：0元、最小、最大、小数精度、负数。
- 异常：余额不足、支付超时、网络中断、重复支付、并发支付。
- 状态流转：支付中/成功/失败/退款状态正确且不可逆错乱。
- 安全（重点）：前端金额篡改、越权支付他人订单、幂等性（防重复扣款）。
- 对账：订单金额与实付一致、退款金额正确。
**【一句话总结】** 重点测金额边界、并发重复支付、状态流转、金额篡改与越权、幂等防重复扣款和对账一致。

**17. 如何设计购物车的测试用例？**
- 添加：正常添加、已下架商品、库存不足、加入数量超库存。
- 修改：增减数量、数量为0、删除、清空。
- 计算（重点）：单品小计、多品合计、优惠券满减、运费，金额计算准确。
- 状态：商品价格变动、失效商品提示、勾选/取消勾选联动。
- 并发：多端同时操作同一账号购物车数据一致。
**【一句话总结】** 重点验证增删改数量、各种优惠下的金额计算准确性，以及多端并发下的数据一致性。

**18. 需求评审时你会关注什么？**
需求是否完整、明确、无歧义、可测试；业务逻辑是否自洽；异常与边界场景是否定义；与现有功能是否冲突；性能/兼容/安全等非功能要求是否明确；是否有清晰的验收标准。评审阶段发现问题成本最低。
**【一句话总结】** 关注需求的完整性、明确性、可测性、异常边界覆盖和验收标准，尽早在评审阶段发现问题。

**19. 需求文档不完善，如何开展测试？**
多渠道补齐信息：参考原型图、UI稿、竞品、历史版本；主动与产品/开发沟通确认；基于经验做探索性测试；列出假设清单让相关方确认；把不明确点作为风险显式上报，避免背锅。
**【一句话总结】** 靠原型竞品补信息、主动沟通确认、探索性测试兜底，并把模糊点列成风险上报。

**20. 什么是探索性测试？什么时候用？**
探索性测试是"边学习系统、边设计用例、边执行"的动态测试方法，不依赖预先写好的详细用例，测试人员根据实时反馈调整策略。适合需求不明确、时间紧、新功能快速验证或补充脚本化测试的盲区。
**【一句话总结】** 探索性测试是边学边测边调整的动态方法，适合需求不清、时间紧或补脚本化测试盲区。

**21. 如何减少漏测？**
需求阶段深度评审、用例交叉评审、用覆盖率工具度量、加强边界与异常场景设计、探索性测试补盲、建立缺陷知识库、每次漏测做根因复盘并沉淀为新用例。
**【一句话总结】** 靠需求评审、用例评审、覆盖率度量、异常补充、漏测复盘沉淀用例，形成闭环持续减少漏测。

## 三、自动化测试

**22. 测试开发和普通功能测试的区别？**
普通功能测试侧重手工执行用例、发现缺陷；测试开发侧重用编码能力开发自动化框架、测试工具与测试平台、搭建 CI/CD，从"执行者"变为"效率工具的建设者"，核心区分点是编程能力与工程思维。
**【一句话总结】** 功能测试重手工执行找 Bug，测试开发重用代码造工具、框架和平台来提升整体测试效率。

**23. 什么样的项目/功能适合做自动化？**
适合：需求稳定、迭代周期长、回归频繁、手工重复度高、核心业务流程、接口稳定的模块。
不适合：需求频繁变动、一次性项目、UI频繁改动、易用性/探索性测试。
判断核心：投入产出比（ROI），能长期复用才值得自动化。
**【一句话总结】** 需求稳定、回归频繁、长期复用的核心流程适合自动化，频繁变动或一次性的不适合。

**24. 自动化测试金字塔模型是什么？**
自下而上：
- 单元测试（底层）：数量最多、成本最低、最稳定、最快。
- 接口/集成测试（中层）：性价比最高，稳定且覆盖业务逻辑，应重点投入。
- UI 测试（顶层）：数量最少、成本最高、最脆弱。
理念：投入应"底多顶少"，避免"冰淇淋反模式"（UI 测试过多）。
**【一句话总结】** 金字塔理念是底层单元测试最多、中层接口测试性价比最高、顶层 UI 测试最少最脆弱。

**25. 常用自动化测试框架有哪些？**
- 接口：Requests+Pytest、RestAssured、HttpRunner、Postman/Newman。
- Web UI：Selenium、Playwright、Cypress。
- 移动端：Appium、UIAutomator2、XCUITest。
- 单元：pytest、unittest、JUnit、TestNG。
**【一句话总结】** 接口用 Requests+Pytest，UI 用 Selenium/Playwright，移动端用 Appium，单元用 pytest/JUnit。

**26. Selenium 的三种等待方式？**
- 强制等待 `time.sleep()`：固定死等，浪费时间，不推荐。
- 隐式等待 `implicitly_wait()`：全局设置，找不到元素时在超时内轮询，作用于所有元素。
- 显式等待 `WebDriverWait + expected_conditions`：针对特定元素/条件等待，最灵活、最推荐。
注意：隐式和显式不建议混用，可能导致等待时间叠加、行为不可预测。
**【一句话总结】** 强制等待死等不用、隐式等待全局生效、显式等待针对条件最灵活推荐，二者别混用。

**27. Selenium 定位元素的方式？如何提高稳定性？**
定位方式：id、name、class_name、tag_name、link_text、partial_link_text、xpath、css_selector。
提高稳定性：优先用唯一 id；避免绝对路径 XPath，用相对定位；结合显式等待；不依赖动态生成的属性；必要时让开发加测试专用属性（如 data-testid）。
**【一句话总结】** 有八种定位方式，优先用唯一 id、相对定位加显式等待，避免绝对路径和动态属性提高稳定性。

**28. 什么是 PO（Page Object）设计模式？好处？**
PO 模式把每个页面的元素定位和操作方法封装成独立的 Page 类，测试用例只调用页面方法，实现"测试逻辑"与"页面元素"分离。好处：页面变动只需改对应 Page 类、代码复用率高、可维护性和可读性强。
**【一句话总结】** PO 模式把页面元素和操作封装成类，实现测试逻辑与页面分离，页面一改只需改一处，好维护。

**29. 如何处理弹窗、iframe、多窗口？**
- 弹窗(alert)：`driver.switch_to.alert.accept()/dismiss()`。
- iframe：`switch_to.frame()` 进入，操作完 `switch_to.default_content()` 返回。
- 多窗口/标签页：`window_handles` 拿所有句柄，`switch_to.window(handle)` 切换。
**【一句话总结】** 弹窗用 switch_to.alert，iframe 用 switch_to.frame 进出，多窗口用 window_handles 切句柄。

**30. 如何处理自动化中元素定位不到/不稳定？**
逐项排查：加显式等待确保元素可见可点击；检查是否在 iframe 内需切换；检查是否动态 id 换稳定属性；检查是否有弹窗遮挡；滚动到元素可见区域；检查是否新窗口需切换句柄。
**【一句话总结】** 先加显式等待，再依次查 iframe、动态id、弹窗遮挡、滚动可见、窗口切换等常见原因。

**31. 自动化测试如何做数据驱动？**
把测试数据与测试逻辑分离，用一套脚本跑多组数据。实现：pytest 的 `@pytest.mark.parametrize` 参数化，或从外部文件（Excel/CSV/YAML/JSON）、数据库读取数据。好处：新增场景只加数据不改代码。
**【一句话总结】** 数据驱动是数据与脚本分离，用 parametrize 或读外部文件让一套脚本跑多组数据。

**32. pytest 有哪些核心功能？**
- Fixture：前置后置资源管理，支持作用域（function/class/module/session）。
- 参数化：`@pytest.mark.parametrize`。
- 标记分组：`@pytest.mark.smoke` 按需执行。
- 断言：直接用 assert，失败信息友好。
- conftest.py：共享 fixture 和配置。
- 丰富插件：pytest-html（报告）、pytest-xdist（并行）、pytest-rerunfailures（失败重跑）、allure-pytest（Allure 报告）。
**【一句话总结】** pytest 有 fixture、参数化、标记分组、友好断言、conftest 共享和丰富插件，是主流测试框架。

**33. fixture 和传统 setup/teardown 的区别？**
fixture 更灵活强大：可指定作用域按需初始化、可参数化、可相互依赖、通过 yield 优雅实现前置与清理、可按需注入到用例。setup/teardown 只能按固定层级执行，灵活性差。
**【一句话总结】** fixture 比 setup/teardown 更灵活，支持作用域、参数化、依赖注入和 yield 清理。

**34. 如何减少自动化中的 Flaky（不稳定）用例？**
用显式等待代替固定等待；测试数据独立、每个用例自建自销；用例间无依赖、不依赖执行顺序；隔离测试环境;失败自动重试;定期维护失效用例;避免依赖不稳定的第三方接口（可 mock）。
**【一句话总结】** 靠显式等待、数据独立、用例解耦、环境隔离、失败重试和定期维护来减少不稳定用例。

**35. 什么是持续集成(CI)？自动化如何接入 CI/CD？**
CI 指频繁将代码集成到主干并自动构建、测试。接入流程：代码提交触发 Jenkins/GitLab CI/GitHub Actions → 自动拉代码、构建、部署测试环境 → 运行自动化用例 → 生成测试报告（Allure）→ 结果通知（钉钉/企业微信/邮件）。实现"提交即测试"。
**【一句话总结】** CI 是提交代码自动构建测试，自动化接入后实现提交即触发用例执行、生成报告并通知。

**36. 接口自动化和 UI 自动化的区别？**
- 接口自动化：直接测接口，快、稳定、维护成本低，可早期介入，但测不到 UI 展现。
- UI 自动化：模拟真实用户操作，覆盖端到端，但慢、脆弱、维护成本高。
实践建议：优先做接口自动化，UI 自动化只覆盖最核心的端到端流程。
**【一句话总结】** 接口自动化快稳维护低应重点做，UI 自动化真实但脆弱只覆盖核心流程。

**37. 如何设计一个自动化测试框架？**
分层设计：用例层 + 业务/关键字层 + 页面对象层（UI）/接口封装层 + 工具层（请求封装、日志、断言、数据处理）+ 配置层（多环境）+ 报告层（Allure）。核心能力：数据驱动、日志记录、失败重试、异常处理、CI 集成、多环境配置。
**【一句话总结】** 分层设计（用例/业务/页面或接口/工具/配置/报告），集成数据驱动、日志、报告、重试和 CI。

## 四、接口测试

**38. 什么是接口测试？为什么它性价比高？**
接口测试是对系统组件之间的接口（如 HTTP API）进行验证，检查接口的功能、逻辑、数据、异常处理是否正确。性价比高的原因：可在前后端并行开发时提前介入、不依赖 UI 因而更稳定更快、能覆盖 UI 难以触发的异常与边界场景、维护成本远低于 UI 自动化。
**【一句话总结】** 接口测试直接测组件间接口，能早介入、快而稳、能测 UI 触发不到的异常，性价比最高。

**39. 接口测试主要测哪些内容？**
- 功能：请求方法、URL、参数、返回状态码、响应字段与数据类型、业务逻辑正确性。
- 异常：参数缺失、类型错误、超长、非法值、越权访问。
- 安全：鉴权、越权、SQL注入、敏感信息是否加密/脱敏。
- 性能：响应时间、并发能力。
- 其他：幂等性、事务一致性、数据一致性。
**【一句话总结】** 测功能正确性、异常参数、安全鉴权越权、性能并发，以及幂等和数据一致性。

**40. GET 和 POST 的区别？**
GET 参数拼在 URL、有长度限制、可被缓存、幂等、用于查询数据；POST 参数在请求体、无明显长度限制、不缓存、非幂等、用于提交或修改数据，相对更安全（参数不暴露在 URL）。
**【一句话总结】** GET 参数在URL用于查询、幂等可缓存，POST 参数在body用于提交、非幂等更安全。

**41. 常见的 HTTP 状态码？**
2xx 成功（200 OK、201 已创建）；3xx 重定向（301 永久、302 临时、304 未修改用缓存）；4xx 客户端错误（400 参数错误、401 未认证、403 无权限、404 未找到、405 方法不允许）；5xx 服务端错误（500 内部错误、502 网关错误、503 服务不可用、504 网关超时）。
**【一句话总结】** 2xx成功、3xx重定向、4xx客户端错误（400参数/401未认证/403无权限/404未找到）、5xx服务端错误。

**42. Cookie、Session、Token 的区别？**
- Cookie：存在客户端浏览器，有大小限制，可被篡改，用于保存少量状态。
- Session：数据存在服务端，通过 SessionID（通常放在 Cookie）关联，更安全但服务端需存储、不利于分布式。
- Token(如 JWT)：无状态，服务端不存储，自身携带用户信息和签名，适合前后端分离和分布式/集群。
**【一句话总结】** Cookie 存客户端、Session 存服务端更安全、Token 无状态适合分布式，是三种会话保持方案。

**43. 接口存在依赖（如登录后才能操作），如何处理？**
先调用前置接口获取数据（如登录拿到 Token），从其响应中提取关键字段（JSONPath/正则/Header 提取），再作为参数传给后续接口。代码中用变量传递或 pytest fixture 管理前置依赖，工具中用"关联/变量"功能实现。
**【一句话总结】** 先调前置接口取数据（如登录拿Token），提取关键字段再传给后续接口，用变量或fixture管理依赖。

**44. 什么是接口幂等性？如何测试？**
幂等指同一请求执行一次和执行多次的结果一致，不会重复产生副作用（如重复支付、重复下单、重复扣款）。测试方法：用完全相同的参数连续多次调用接口，验证只生效一次。实现通常靠唯一订单号、token 或数据库唯一约束保证。
**【一句话总结】** 幂等是同一请求多次调用结果一致不重复生效，测试就是用相同参数多次调用验证只生效一次。

**45. 如何进行接口鉴权与越权测试？**
常见鉴权方式：Basic Auth、API Key、Token/JWT、OAuth2.0、签名验签。测试点：无 Token 访问被拒、错误/过期 Token 被拒、水平越权（改 ID 访问他人数据）、垂直越权（普通用户调管理员接口）、Token 是否可伪造篡改。
**【一句话总结】** 测无Token、错误/过期Token被拦，重点测水平越权（改ID看他人）和垂直越权（越级调高权限接口）。

**46. 如何测试一个"用户注册"接口？**
- 正常：合法参数注册成功。
- 参数校验：必填缺失、类型错误、超长、特殊字符、格式（手机号/邮箱/密码强度）。
- 业务：重复注册（用户名/手机号已存在）、验证码校验、并发注册同一账号。
- 安全：SQL注入、XSS、密码是否加密存储、响应是否返回敏感信息。
- 返回：状态码、错误码、提示信息是否准确。
**【一句话总结】** 从正常、参数校验、业务重复注册、安全注入加密、返回信息五方面覆盖，重点是重复注册和并发。

**47. 什么是 Mock？为什么要 Mock 接口？**
Mock 是模拟真实接口返回预设数据。使用场景：依赖的接口尚未开发完成（前后端并行）、第三方接口不稳定或收费、难以构造的异常场景（如超时、特定错误码）、需要隔离测试对象。工具：Postman Mock、WireMock、Moco、mockjs、unittest.mock。
**【一句话总结】** Mock 是模拟接口返回预设数据，用于依赖未就绪、第三方不稳定或构造异常场景，实现并行和隔离测试。

**48. 常用的接口测试与抓包工具？**
- 接口测试：Postman、Apifox、JMeter、SoapUI。
- 代码框架：Requests+Pytest、RestAssured、HttpRunner。
- 抓包分析：Charles、Fiddler、Wireshark、mitmproxy、Burp Suite。
**【一句话总结】** 手工用Postman/Apifox，代码用Requests+Pytest，抓包用Charles/Fiddler/Burp。

## 五、性能测试

**49. 什么是性能测试？和功能测试的区别？**
性能测试验证系统在特定负载下的响应时间、吞吐量、资源占用等指标是否满足要求。功能测试关注"功能对不对、能不能用"，性能测试关注"在压力下快不快、稳不稳、扛不扛得住"。
**【一句话总结】** 功能测试看能不能用，性能测试看在负载下响应快不快、吞吐够不够、系统扛不扛得住。

**50. 性能测试有哪些分类？**
- 负载测试：逐步加压，找到满足指标下系统能承受的最大负载。
- 压力测试：持续加压直到系统崩溃，找系统极限和瓶颈。
- 并发测试：多用户同一时刻操作，测并发处理能力和数据一致性。
- 稳定性/疲劳测试：长时间运行，检测内存泄漏和性能衰减。
- 容量测试：确定系统能支撑的最大数据量/用户量。
- 基准测试：单用户下的性能基线。
**【一句话总结】** 负载找最大承载、压力找崩溃极限、并发测同时操作、稳定性测长时间跑，容量测最大支撑量。

**51. 性能测试的核心指标有哪些？**
- 响应时间(RT)：从请求发出到收到响应的耗时（用户最直观感受）。
- 吞吐量(TPS/QPS)：每秒处理的事务数/查询数（系统处理能力核心指标）。
- 并发用户数：同时向系统发请求的用户数。
- 错误率：失败请求占比。
- 资源利用率：CPU、内存、磁盘I/O、网络带宽。
**【一句话总结】** 核心是响应时间RT、吞吐量TPS、并发数、错误率和资源利用率，TPS和RT最关键。

**52. TPS、RT、并发数三者的关系？**
经验公式：并发数 ≈ TPS × 平均响应时间(RT)，即 TPS = 并发数 / RT。当并发增大，TPS 上升；达到系统瓶颈后，TPS 不再增长甚至下降，而 RT 急剧上升，此拐点即系统最大处理能力。
**【一句话总结】** 并发数≈TPS×RT，并发增大TPS上升，到拐点后TPS不再涨而RT飙升，拐点即系统极限。

**53. 常用性能测试工具？**
- JMeter：开源、功能全、社区大，最常用。
- LoadRunner：商业，功能强大。
- Locust：用 Python 写脚本，易扩展、易上手。
- Gatling：Scala 编写，高性能。
- wrk/ab：轻量命令行压测。
**【一句话总结】** 最常用开源JMeter，商业用LoadRunner，Python生态用Locust，轻量压测用wrk/ab。

**54. JMeter 的核心组件有哪些？**
- 线程组：模拟并发用户（设置线程数、循环、加压方式）。
- 取样器(Sampler)：发送请求（HTTP/JDBC等）。
- 逻辑控制器：控制执行逻辑（循环、条件、事务）。
- 配置元件：CSV数据文件、HTTP默认值、Cookie管理。
- 定时器：控制请求间隔，模拟真实用户思考时间。
- 断言：验证响应正确性。
- 监听器：查看结果（聚合报告、结果树、图形）。
- 前置/后置处理器：参数化、关联提取。
**【一句话总结】** 核心是线程组模拟并发、取样器发请求、断言验结果、监听器看报告，配以定时器和参数化。

**55. 如何设计一个性能测试方案？**
明确目标与指标（TPS、RT 要求）→ 分析业务模型（核心场景及占比）→ 设计测试场景（并发数、加压方式、持续时长）→ 准备数据与环境（尽量贴近生产）→ 编写并调试脚本 → 执行并全程监控 → 分析结果定位瓶颈 → 优化后回归验证 → 输出性能测试报告。
**【一句话总结】** 定目标→分析业务模型→设计场景→备环境数据→执行监控→定位瓶颈→优化回归→出报告，全流程闭环。

**56. 性能测试如何定位瓶颈？**
从前到后逐层排查：压测机自身是否成瓶颈 → 网络带宽延迟 → 应用层（线程池、连接池、代码算法、GC、锁）→ 中间件（Web服务器、缓存配置）→ 数据库（慢SQL、索引、锁、连接数）→ 硬件资源（CPU、内存、磁盘I/O）。借助 APM 工具（SkyWalking、Arthas）、top、jstack、慢查询日志分析。
**【一句话总结】** 从压测机、网络、应用、中间件、数据库到硬件逐层排查，用APM、top、jstack、慢查询日志辅助定位。

**57. 响应时间慢可能有哪些原因？**
数据库慢SQL/缺索引/锁竞争；代码逻辑差、循环调用、大量计算；缓存未命中或未用缓存；线程池/连接池不足导致排队；频繁 GC（内存不足）；网络延迟或带宽瓶颈；外部依赖接口慢。
**【一句话总结】** 常见是慢SQL缺索引、代码差、缓存没命中、连接池不足排队、频繁GC、网络慢或依赖接口慢。

**58. 什么是内存泄漏？性能测试中如何发现？**
内存泄漏指程序申请的内存无法被回收，导致可用内存持续减少。发现方法：长时间稳定性测试中监控内存曲线，若内存持续增长不回落、Full GC 后仍不下降、最终 OOM，则可能存在泄漏。可用 jmap 导出 heap dump，用 MAT 工具分析定位。
**【一句话总结】** 内存泄漏是内存无法回收，靠长时间稳定性测试看内存持续上涨不回落、频繁FullGC甚至OOM来发现。

**59. 如何确定性能测试的并发数？**
根据生产环境监控/日志估算峰值在线用户数和 PV；用二八原则等公式换算（如80%访问集中在20%时间）；参考业务预估（大促、活动目标）；若无历史数据，用递增加压法逐步找到性能拐点。
**【一句话总结】** 靠生产监控峰值、二八原则估算或业务预估确定，无数据时用递增加压找拐点。

## 六、安全测试

**60. 常见的 Web 安全漏洞有哪些？（OWASP）**
SQL注入、XSS跨站脚本、CSRF跨站请求伪造、越权访问、敏感信息泄露、文件上传漏洞、命令注入、SSRF服务端请求伪造、失效的身份认证、安全配置错误、不安全的反序列化。
**【一句话总结】** 高频是SQL注入、XSS、CSRF、越权、敏感信息泄露和文件上传，即OWASP Top 10 核心项。

**61. 什么是 SQL 注入？如何防范？**
攻击者在输入中拼接恶意 SQL 语句，改变原查询逻辑，达到绕过登录、窃取或篡改数据的目的（如输入 `' or 1=1 --`）。防范：使用预编译/参数化查询（PreparedStatement）、使用 ORM、输入校验与过滤、数据库账号最小权限、关闭详细报错信息。
**【一句话总结】** SQL注入是拼接恶意SQL改变查询逻辑，用预编译参数化查询+输入校验+最小权限防范。

**62. 什么是 XSS？有哪几种类型？如何防范？**
XSS（跨站脚本）指攻击者注入恶意脚本到页面，在受害者浏览器执行，窃取 Cookie/会话等。类型：反射型（恶意脚本在URL参数，需诱导点击）、存储型（存入数据库，危害最大，所有访问者都中招）、DOM型（前端JS处理不当）。防范：输入过滤、输出编码转义、Cookie设HttpOnly、启用CSP内容安全策略。
**【一句话总结】** XSS是注入脚本在他人浏览器执行，分反射/存储/DOM型，用输入过滤+输出转义+HttpOnly+CSP防范。

**63. 什么是 CSRF？如何防范？和 XSS 的区别？**
CSRF（跨站请求伪造）指诱导已登录用户在不知情下发起恶意请求，借用其身份和 Cookie 完成操作。防范：CSRF Token、校验 Referer/Origin、Cookie 设 SameSite 属性、敏感操作二次验证。
与XSS区别：XSS是注入并执行恶意脚本，利用用户对网站的信任；CSRF是伪造用户请求，利用网站对用户浏览器（Cookie）的信任，无需注入脚本。
**【一句话总结】** CSRF是借用户身份伪造请求，用Token+校验Referer+SameSite防范；XSS注入脚本，CSRF伪造请求，信任方向相反。

**64. 什么是越权漏洞？分哪两类？如何测试？**
越权指用户访问了本无权限访问的资源或功能。
- 水平越权：访问同级别其他用户的数据（如改 URL 中 userId 查看他人订单）。
- 垂直越权：低权限用户访问高权限功能（如普通用户直接调管理员接口）。
测试：抓包修改请求中的资源 ID、越级调用高权限接口、篡改参数，验证是否被服务端拦截（不能只靠前端隐藏）。
**【一句话总结】** 越权是访问了无权限的资源，分水平（看他人数据）和垂直（越级用高权限），靠改ID和越级调接口测。

**65. 敏感信息泄露有哪些表现？如何测试？**
表现：接口返回明文密码/身份证/手机号未脱敏；报错信息暴露堆栈/SQL/服务器信息；HTTP 明文传输；URL 携带敏感参数；备份文件、日志、.git/.svn 等可被下载。测试：抓包检查响应内容与传输是否加密、构造异常看报错、扫描敏感路径与备份文件。
**【一句话总结】** 表现为明文密码、报错暴露信息、明文传输、敏感文件可下载，靠抓包、构造异常和扫描路径测试。

**66. 密码相关的安全测试点有哪些？**
传输加密（HTTPS）；存储加密（加盐哈希，禁明文或可逆加密）；密码强度校验；登录失败次数限制与账号锁定；找回密码流程防越权、验证码防爆破；密码框不回显；密码不记录到日志。
**【一句话总结】** 测传输加密、加盐存储、强度校验、失败锁定、找回防越权、不回显不记日志。

**67. 什么是文件上传漏洞？如何防范？**
攻击者上传可执行脚本（如 webshell）到服务器并执行，获取服务器控制权。防范：白名单校验文件类型（不只看后缀，校验文件头/MIME）、上传后重命名文件、限制大小、上传目录禁止执行权限、文件隔离存储、内容安全扫描。
**【一句话总结】** 上传漏洞是传木马拿服务器权限，用白名单校验文件头+重命名+目录禁执行+隔离存储防范。

**68. 什么是暴力破解？如何防范？**
攻击者用大量账号/密码组合自动尝试登录以猜出正确凭据。防范：登录失败次数限制与账号锁定、图形/滑动/短信验证码、IP 限流、二次认证(2FA)、密码复杂度要求、异常登录告警。
**【一句话总结】** 暴力破解是海量尝试猜密码，用失败锁定+验证码+IP限流+二次认证+异常告警防范。

**69. HTTP 和 HTTPS 的区别？HTTPS 如何保证安全？**
HTTP 明文传输，HTTPS 在 HTTP 基础上加 SSL/TLS 加密层。HTTPS 通过：非对称加密协商出对称密钥 → 用对称加密传输数据（兼顾安全与性能）→ 数字证书验证服务端身份（防冒充）→ 数据完整性校验（防篡改），从而防窃听、防篡改、防冒充。
**【一句话总结】** HTTPS是HTTP加SSL/TLS加密，用非对称协商密钥+对称传数据+证书验身份，防窃听篡改冒充。

**70. 常用的安全测试工具？**
- 抓包/代理：Burp Suite（最常用）、Fiddler、Charles、mitmproxy。
- 漏洞扫描：AWVS、AppScan、OWASP ZAP、Nessus、Xray。
- 注入：sqlmap。
- 端口扫描：Nmap。
- 综合渗透：Metasploit。
**【一句话总结】** 最常用抓包渗透用Burp Suite，漏洞扫描用AWVS/ZAP，注入用sqlmap，端口扫描用Nmap。

## 七、算法（10 道经典算法面试题）

**A1. 反转链表（LeetCode 206）**
经典高频题。用三个指针（prev、cur、next）迭代反转指向。
```python
def reverse_list(head):
    prev = None
    cur = head
    while cur:
        nxt = cur.next   # 暂存下一个节点
        cur.next = prev  # 反转指向
        prev = cur       # prev 前移
        cur = nxt        # cur 前移
    return prev          # prev 即新头节点
```
时间 O(n)，空间 O(1)。
**【一句话总结】** 用 prev/cur/next 三指针迭代，逐个把 next 指针反向，最后返回 prev。

**A2. 判断链表是否有环（LeetCode 141，快慢指针）**
快指针一次走两步，慢指针一次走一步，若有环两者必相遇，无环快指针先到 None。
```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            return True
    return False
```
**【一句话总结】** 快慢指针，快2慢1，相遇则有环，否则快指针到头即无环。

**A3. 二分查找（LeetCode 704）**
在有序数组中查找目标，每次折半缩小范围。
```python
def binary_search(nums, target):
    left, right = 0, len(nums) - 1
    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1
    return -1
```
时间 O(logn)。注意点：`left <= right`、`mid+1/mid-1` 防死循环。
**【一句话总结】** 有序数组每次取中间比较，大了往左找小了往右找，时间复杂度 O(logn)。

**A4. 有效的括号（LeetCode 20，栈应用）**
用栈存左括号，遇右括号判断是否与栈顶匹配。
```python
def is_valid(s):
    stack = []
    pairs = {')': '(', ']': '[', '}': '{'}
    for c in s:
        if c in '([{':
            stack.append(c)
        else:
            if not stack or stack.pop() != pairs[c]:
                return False
    return not stack
```
**【一句话总结】** 用栈，左括号入栈，右括号出栈匹配，最后栈空则合法。

**A5. 合并两个有序数组 / 链表（LeetCode 21）**
双指针依次比较较小者放入结果。
```python
def merge_lists(l1, l2):
    dummy = cur = ListNode(0)
    while l1 and l2:
        if l1.val <= l2.val:
            cur.next, l1 = l1, l1.next
        else:
            cur.next, l2 = l2, l2.next
        cur = cur.next
    cur.next = l1 or l2  # 拼接剩余部分
    return dummy.next
```
**【一句话总结】** 双指针比较两表头，小的接到结果链表，最后拼接剩余节点。

**A6. 最大子数组和（LeetCode 53，动态规划/Kadane）**
遍历时维护"以当前元素结尾的最大和"，取全局最大。
```python
def max_subarray(nums):
    cur = res = nums[0]
    for n in nums[1:]:
        cur = max(n, cur + n)   # 要么接前面，要么重新开始
        res = max(res, cur)
    return res
```
时间 O(n)。
**【一句话总结】** Kadane 算法，遍历时若前面的和为负就丢弃重新累加，全程记录最大值。

**A7. 爬楼梯（LeetCode 70，动态规划入门）**
每次爬 1 或 2 阶，`f(n)=f(n-1)+f(n-2)`，本质是斐波那契。
```python
def climb_stairs(n):
    a, b = 1, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```
**【一句话总结】** 到第 n 阶等于到 n-1 和 n-2 阶方法数之和，即斐波那契，用双变量滚动。

**A8. 两数之和的进阶：三数之和（LeetCode 15，双指针）**
先排序，固定一个数，剩余用双指针从两端逼近。
```python
def three_sum(nums):
    nums.sort()
    res = []
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i-1]:
            continue  # 去重
        l, r = i + 1, len(nums) - 1
        while l < r:
            s = nums[i] + nums[l] + nums[r]
            if s == 0:
                res.append([nums[i], nums[l], nums[r]])
                while l < r and nums[l] == nums[l+1]: l += 1
                while l < r and nums[r] == nums[r-1]: r -= 1
                l += 1; r -= 1
            elif s < 0:
                l += 1
            else:
                r -= 1
    return res
```
**【一句话总结】** 排序后固定一个数，剩下两个数用双指针左右逼近求和为 0，注意去重。

**A9. 无重复字符的最长子串（LeetCode 3，滑动窗口）**
用滑动窗口 + 哈希集合，右指针扩张，遇重复则左指针收缩。
```python
def length_of_longest(s):
    seen = set()
    left = res = 0
    for right in range(len(s)):
        while s[right] in seen:
            seen.remove(s[left])
            left += 1
        seen.add(s[right])
        res = max(res, right - left + 1)
    return res
```
时间 O(n)。
**【一句话总结】** 滑动窗口，右指针扩张、遇重复左指针收缩，窗口内始终无重复，记录最大长度。

**A10. 二叉树的层序遍历（LeetCode 102，BFS）**
用队列逐层遍历，每层节点数量决定一层的处理范围。
```python
from collections import deque

def level_order(root):
    if not root:
        return []
    res, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):  # 当前层节点数
            node = queue.popleft()
            level.append(node.val)
            if node.left: queue.append(node.left)
            if node.right: queue.append(node.right)
        res.append(level)
    return res
```
**【一句话总结】** 用队列做 BFS，每次记录当前层节点数逐层出队，孩子入队，实现按层遍历。

## 八、编程（20 道高频面试题）

> Python 语言特性、内存、并发、常用技巧类高频题（与前篇不重复）。

**P1. Python 中的可变对象和不可变对象有哪些？**
- 不可变：int、float、str、tuple、bool、frozenset（值不能原地修改，改动会创建新对象）。
- 可变：list、dict、set（可原地修改）。
影响：不可变对象作函数参数传递不会影响原值，可变对象会。
**【一句话总结】** 数字、字符串、元组不可变，列表、字典、集合可变，可变对象作参数会被函数内部修改。

**P2. Python 函数参数是值传递还是引用传递？**
Python 是"传对象引用"(pass by object reference)。传不可变对象时表现类似值传递（内部修改不影响外部），传可变对象时内部修改会影响外部。
**【一句话总结】** Python 传的是对象引用，改不可变对象不影响外部，改可变对象会影响外部。

**P3. Python 中 *args 和 **kwargs 的作用？**
- `*args`：接收任意数量的位置参数，打包成元组。
- `**kwargs`：接收任意数量的关键字参数，打包成字典。
用于函数参数不确定或做装饰器透传。
**【一句话总结】** *args 收多余位置参数成元组，**kwargs 收关键字参数成字典，实现不定参数。**

**P4. Python 装饰器是什么？作用？**
装饰器是一个返回函数的函数，在不修改原函数代码的前提下增强其功能（如日志、计时、鉴权、重试）。
```python
def timer(func):
    def wrapper(*args, **kwargs):
        import time
        start = time.time()
        result = func(*args, **kwargs)
        print(f"耗时: {time.time() - start}")
        return result
    return wrapper

@timer
def task():
    ...
```
测试中常用于失败重试、用例标记、性能统计。
**【一句话总结】** 装饰器是不改源码给函数加功能的高阶函数，测试中常用于计时、重试、日志。

**P5. Python 中的浅拷贝和深拷贝如何实现？**
```python
import copy
b = copy.copy(a)      # 浅拷贝，只复制外层
c = copy.deepcopy(a)  # 深拷贝，递归复制所有层
```
浅拷贝内层嵌套对象仍共享引用，深拷贝完全独立。
**【一句话总结】** copy.copy 只复制一层内层仍共享，copy.deepcopy 递归复制完全独立。

**P6. Python 中如何实现单例模式？**
常用方法：装饰器、`__new__`、模块（Python 模块天然单例）、元类。
```python
def singleton(cls):
    instances = {}
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance
```
**【一句话总结】** 保证一个类只有一个实例，可用装饰器、__new__ 或模块导入实现。

**P7. Python 的 GIL 是什么？有什么影响？**
GIL(全局解释器锁)保证同一时刻只有一个线程执行 Python 字节码。
影响：CPU 密集型任务多线程无法真正并行（用多进程 multiprocessing 绕过）；I/O 密集型任务多线程仍有效（等待 I/O 时释放 GIL）。
**【一句话总结】** GIL 让同一时刻只有一个线程执行，CPU 密集用多进程，I/O 密集用多线程仍有效。

**P8. Python 中进程、线程、协程的区别？**
- 进程：资源独立，开销大，适合 CPU 密集，用 multiprocessing。
- 线程：共享内存，受 GIL 限制，适合 I/O 密集，用 threading。
- 协程：单线程内用户态切换，开销极小，高并发 I/O，用 asyncio/gevent。
**【一句话总结】** 进程重适合CPU密集，线程轻适合I/O密集，协程最轻单线程高并发I/O。

**P9. Python 的生成器(generator)是什么？和列表的区别？**
生成器用 yield 惰性产生值，不一次性把所有数据放内存，节省内存，适合处理大数据。列表会立即计算并全部存内存。
```python
def gen():
    for i in range(1000000):
        yield i   # 用时才计算，省内存
```
**【一句话总结】** 生成器用 yield 惰性求值、按需生成、省内存，列表一次性全部载入内存。

**P10. Python 中 is 和 == 的区别？为什么小整数 is 会相等？**
- `==` 比较值，`is` 比较内存地址(是否同一对象)。
- Python 对 -5~256 的小整数做了缓存(小整数池)，同值指向同一对象，所以 `is` 为 True。
**【一句话总结】** == 比值，is 比地址，小整数 -5~256 被缓存所以 is 也相等。

**【一句话总结】** try 捕获、except 分类处理、else 无异常执行、finally 必执行用于清理资源。

**P12. Python 中列表推导式和字典推导式怎么写？**

**【一句话总结】** sort 原地改列表，sorted 返回新列表，用 key 参数自定义排序规则。

**P17. Python 中 lambda 匿名函数怎么用？**
用于定义简单的一次性函数，常配合 map/filter/sorted/reduce 使用。
```python
add = lambda x, y: x + y
list(map(lambda x: x*2, nums))
list(filter(lambda x: x > 0, nums))
```
**【一句话总结】** lambda 定义一行匿名函数，常配合 map/filter/sorted 处理数据。

**P18. Python 中如何反转字典的键值？**
```python
new_dict = {v: k for k, v in d.items()}
```
注意：值有重复时会覆盖，反转后 key 需唯一。
**【一句话总结】** 用字典推导 {v:k for k,v in d.items()} 交换键值，注意值重复会覆盖。

**P19. Python 中 range 和 xrange 的区别？（Py2 vs Py3）**
- Python 2：range 返回列表，xrange 返回惰性可迭代对象。
- Python 3：只有 range，且行为等同于 Py2 的 xrange（惰性、省内存）。
**【一句话总结】** Python3 的 range 是惰性对象省内存，Python2 的 xrange 才是惰性、range 返回列表。

**P20. Python 中如何实现多线程/多进程（简单示例）？**
```python
# 多线程（I/O 密集）
from threading import Thread
t = Thread(target=func, args=(x,)); t.start(); t.join()

# 多进程（CPU 密集）
from multiprocessing import Process
p = Process(target=func, args=(x,)); p.start(); p.join()

# 线程池
from concurrent.futures import ThreadPoolExecutor
with ThreadPoolExecutor(max_workers=5) as pool:
    results = pool.map(func, data)
```
**【一句话总结】** I/O密集用 threading，CPU密集用 multiprocessing，推荐用线程/进程池统一管理。

## 九、数据库

> 基础 SQL + 索引/事务/锁/优化进阶，每题附一句话总结。

**D1. 内连接、左连接、右连接的区别？**
- 内连接(INNER JOIN)：只返回两表匹配的行。
- 左连接(LEFT JOIN)：返回左表全部行 + 右表匹配行，右表无匹配补 NULL。
- 右连接(RIGHT JOIN)：返回右表全部行 + 左表匹配行，左表无匹配补 NULL。
**【一句话总结】** 内连接只留匹配行，左连接保左表全部、右连接保右表全部，未匹配补NULL。

**D2. 查询每个部门工资最高的员工（经典 SQL）。**
```sql
SELECT e.* FROM emp e
WHERE e.salary = (
  SELECT MAX(salary) FROM emp WHERE dept_id = e.dept_id
);
```
**【一句话总结】** 用关联子查询，取每个部门内 salary 等于该部门最大值的员工。

**D3. 查询第二高的工资（经典 SQL）。**
```sql
SELECT MAX(salary) FROM emp
WHERE salary < (SELECT MAX(salary) FROM emp);
```
**【一句话总结】** 先查最高工资，再查小于最高工资里的最大值即第二高。

**D4. 查询和删除重复数据。**
```sql
-- 查询重复的 name
SELECT name, COUNT(*) FROM student
GROUP BY name HAVING COUNT(*) > 1;
```
**【一句话总结】** 用 GROUP BY 分组加 HAVING COUNT(*)>1 找出重复数据。

**D5. group by、having、where 的区别？**
- where：分组前对行过滤，不能使用聚合函数。
- group by：按指定字段分组。
- having：分组后对组过滤，可以使用聚合函数（如 HAVING COUNT(*)>1）。
执行顺序：where → group by → having。
**【一句话总结】** where分组前过滤行不能用聚合，having分组后过滤组可用聚合，先where后having。

**D6. 事务的 ACID 特性？**
- 原子性(Atomicity)：事务内操作要么全成功要么全失败回滚。
- 一致性(Consistency)：事务前后数据保持一致状态。
- 隔离性(Isolation)：并发事务间相互隔离互不干扰。
- 持久性(Durability)：事务提交后修改永久保存。
**【一句话总结】** ACID即原子性全成或全败、一致性状态守恒、隔离性并发互不干扰、持久性提交永久保存。

**D7. 事务的隔离级别？分别解决什么问题？**
- 读未提交(RU)：可能脏读、不可重复读、幻读。
- 读已提交(RC)：解决脏读，可能不可重复读、幻读。
- 可重复读(RR，MySQL默认)：解决脏读和不可重复读，可能幻读（InnoDB用间隙锁基本解决）。
- 串行化(Serializable)：全部解决，但并发性能最差。
**【一句话总结】** 四级隔离RU/RC/RR/串行化，隔离越高越安全但性能越差，MySQL默认RR。

**D8. 脏读、不可重复读、幻读的区别？**
- 脏读：读到别的事务未提交的数据。
- 不可重复读：同一事务内两次读同一行，数据被别的事务改了导致不一致。
- 幻读：同一事务内两次查询，结果集行数因别的事务增删而变化。
**【一句话总结】** 脏读读到未提交数据，不可重复读是同行数据变了，幻读是结果集行数变了。

**D9. 索引的优缺点？什么时候不走索引？**
优点：大幅加快查询速度。缺点：占用存储空间、降低增删改性能（需维护索引）。
不走索引：like 以%开头、对索引列用函数或运算、隐式类型转换、使用 != / is null（视情况）、or 连接的条件含非索引列、不满足最左前缀、数据量太小。
**【一句话总结】** 索引加快查询但占空间降增删改性能，前导%、函数运算、类型转换、违反最左前缀会失效。

**D10. 索引有哪些类型？为什么用 B+ 树？**
类型：主键索引、唯一索引、普通索引、联合(组合)索引、全文索引。
B+树优势：矮胖结构减少磁盘I/O次数、非叶子节点只存索引键使单页容纳更多、叶子节点用链表相连便于范围查询和排序、所有数据都在叶子层查询性能稳定。
**【一句话总结】** 索引分主键/唯一/普通/联合/全文，用B+树因其矮胖减少IO、叶子链表利于范围查询、性能稳定。

**D11. 什么是覆盖索引？什么是回表？**
- 回表：用普通索引查到主键值后，还需再回到主键索引查完整行数据的过程（两次查找）。
- 覆盖索引：查询所需的字段都包含在索引中，无需回表，直接从索引返回结果，性能更高。
**【一句话总结】** 回表是拿主键再查一次数据，覆盖索引是要查的字段都在索引里无需回表，性能更好。

**D12. 什么是最左前缀原则？**
联合索引 (a,b,c) 的查询必须从最左列开始且连续，才能用到索引：a、a+b、a+b+c 有效；单独 b、c 或 b+c 无法使用该索引。范围查询后的列也无法再用索引。
**【一句话总结】** 联合索引查询必须从最左列开始连续匹配，跳过或断开左列则索引失效。

**D13. 如何定位和优化慢 SQL？**
定位：开启慢查询日志找出慢SQL，用 EXPLAIN 分析执行计划，看是否走索引、扫描行数。
优化：加合适索引、避免 SELECT *、子查询改 JOIN、避免索引列用函数、分页优化（延迟关联）、必要时分库分表。
**【一句话总结】** 用慢查询日志定位、EXPLAIN分析执行计划，靠加索引、避免全表扫描和优化写法来提速。

**D14. EXPLAIN 重点看哪些字段？**
- type：访问类型，性能 system>const>eq_ref>ref>range>index>ALL，出现 ALL 是全表扫描需优化。
- key：实际使用的索引，NULL 表示没走索引。
- rows：预估扫描行数，越少越好。
- Extra：Using index 是覆盖索引（好），Using filesort / Using temporary 需优化。
**【一句话总结】** 重点看type是否ALL全表扫、key有没有走索引、rows扫描行数、Extra有无filesort。

**D15. MySQL 中 InnoDB 和 MyISAM 的区别？**
- InnoDB：支持事务、行锁、外键、崩溃恢复好，MySQL 默认引擎，适合高并发写和事务场景。
- MyISAM：不支持事务、只有表锁、不支持外键，查询快但并发差。
**【一句话总结】** InnoDB支持事务行锁外键适合高并发，MyISAM只表锁不支持事务，现默认用InnoDB。

**D16. 数据库锁有哪些？死锁如何避免？**
锁类型：表锁（粒度大、并发低）、行锁（粒度小、并发高）；共享锁(读锁)、排他锁(写锁)；间隙锁(防幻读)。
死锁：两事务互相持有对方需要的锁而僵持。避免：按固定顺序访问资源、缩小事务范围、设置锁超时、一次性获取所需全部锁。
**【一句话总结】** 有表锁行锁、读写锁、间隙锁；死锁是互相等锁，靠固定加锁顺序、缩短事务、设超时避免。

**D17. count(*)、count(1)、count(字段) 的区别？**
- count(*)：统计所有行（含NULL），InnoDB 有优化，推荐使用。
- count(1)：统计所有行，性能与 count(*) 基本一致。
- count(字段)：只统计该字段非 NULL 的行。
**【一句话总结】** count(*)和count(1)统计所有行且性能相当，count(字段)会忽略NULL值。

**D18. drop、delete、truncate 的区别？**
- delete：DML，删数据可加 where 条件，可回滚，逐行删较慢，不重置自增。
- truncate：DDL，清空整表数据，不可回滚，速度快，重置自增。
- drop：DDL，删除整个表（结构+数据），不可回滚。
**【一句话总结】** delete可条件删可回滚，truncate清空表快但不可回滚，drop删整张表结构，后两者不可回滚。

**D19. 数据库三大范式？**
- 1NF：字段原子性，不可再分。
- 2NF：非主键字段完全依赖主键（消除部分依赖）。
- 3NF：非主键字段不依赖其他非主键字段（消除传递依赖）。
实际中为查询性能常适度反范式（冗余字段）。
**【一句话总结】** 1NF字段不可分、2NF完全依赖主键、3NF无传递依赖，实践中常反范式冗余提性能。

**D20. 如何从测试角度验证数据库层的正确性？**
- 数据准确性：结果符合预期（用边界数据验证）。
- 数据完整性：主键、外键、非空、唯一等约束生效。
- 事务：并发下一致性、异常回滚。
- 性能：EXPLAIN 看执行计划、大数据量响应。
- 安全：SQL 注入、权限控制。
**【一句话总结】** 从数据准确性、完整性约束、事务一致性、性能执行计划、安全注入五方面验证数据库。

### 4.1 文件与目录操作

**L1. 文件/目录常用命令有哪些？**
`ls`(列出)、`cd`(切换)、`pwd`(当前路径)、`mkdir`(建目录)、`touch`(建空文件)、`cp`(复制)、`mv`(移动/重命名)、`rm`(删除，`rm -rf` 递归强制)、`ln -s`(软链接)。
**【一句话总结】** ls/cd/pwd 查看导航，mkdir/touch 创建，cp/mv/rm 复制移动删除，ln -s 建软链接。

**L2. 如何查看文件内容？各命令适用场景？**

**【一句话总结】** cat 看小文件，less 分页看大文件，head/tail 看头尾，tail -f 实时看日志。

**L3. 如何统计文件的行数、单词数、字符数？**

**【一句话总结】** 用 wc 命令，-l 数行、-w 数词、-c 数字节。

### 4.2 文本处理（测试开发高频）

**L4. grep 的常用用法（日志排查核心）？**
```bash
grep "error" app.log          # 查找包含 error 的行
grep -i "error" app.log       # 忽略大小写
grep -n "error" app.log       # 显示行号
grep -c "error" app.log       # 统计匹配行数
grep -v "info" app.log        # 反向匹配(不含 info)
grep -r "keyword" ./dir       # 递归搜索目录
grep -A 3 -B 2 "error" app.log # 匹配行的后3行、前2行
```
**【一句话总结】** grep 查关键字，-i 忽略大小写、-n 显行号、-c 计数、-v 反向、-r 递归、-A/-B 看上下文。

**L5. 如何用 awk 提取某几列 / 处理日志？**
awk 按列处理文本，默认以空格分隔，`$1、$2` 表示第几列。
```bash
awk '{print $1, $4}' access.log      # 打印第1和第4列
awk -F ',' '{print $2}' data.csv     # 以逗号分隔取第2列
awk '{sum+=$1} END{print sum}' nums  # 求和
awk '$3>200 {print $0}' access.log   # 第3列大于200的整行
```
**【一句话总结】** awk 按列处理文本，$n 取第n列，-F 指定分隔符，可做筛选、求和、格式化。

**L6. 如何用 sed 做文本替换？**
sed 是流编辑器，常用于替换文本。
```bash
sed 's/old/new/g' file        # 每行全部替换(仅输出，不改文件)
sed -i 's/old/new/g' file     # -i 直接修改原文件
sed -n '5,10p' file           # 打印第5到10行
sed '/pattern/d' file         # 删除匹配行
```
**【一句话总结】** sed 是流编辑器，s/旧/新/g 替换，-i 改原文件，还能打印指定行、删除匹配行。

**L7. 如何对文件内容排序、去重？**
```bash
sort file             # 排序
sort -n file          # 按数字排序
sort -r file          # 逆序
sort file | uniq      # 去重(需先排序)
sort file | uniq -c   # 统计每行出现次数
```
**【一句话总结】** sort 排序(-n数字-r逆序)，配合 uniq 去重，uniq -c 统计出现次数。

**L8. 场景：统计 access.log 中访问量最高的前 10 个 IP。**
```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
```
思路：提取 IP → 排序 → 统计次数 → 按次数降序 → 取前 10。这是经典组合命令面试题。
**【一句话总结】** awk 取IP、sort排序、uniq -c计数、sort -rn 降序、head -10 取前十，管道串联。

### 4.3 进程与资源

**L9. 如何查看进程？如何结束进程？**
```bash

ps aux | grep nginx      # 查看进程详情
top                      # 实时查看 CPU/内存占用

```
**【一句话总结】** ps -ef 加 grep 查进程，top 看资源，kill 结束进程，kill -9 强制结束。

**L10. 如何查看端口占用？**

**【一句话总结】** 用 netstat -anp 或 lsof -i:端口 或 ss 命令查看端口被哪个进程占用。

**L11. 如何查看系统资源使用情况？**

```bash
top / htop        # CPU、内存实时
```

**L12. 场景：磁盘满了如何排查？**

```bash
df -h                        # 1. 看哪个分区满了
du -sh /* | sort -rh         # 2. 逐层定位大目录
du -sh /var/* | sort -rh     # 3. 深入大目录
find / -type f -size +500M   # 4. 找超大文件
```
思路：先定位满的分区，再逐层 du 找大目录/大文件，常见是日志文件过大。
**【一句话总结】** 先 df -h 定位满的分区，再 du -sh 逐层找大目录，find 找大文件，常是日志堆积。

### 4.4 权限与网络

**L13. 如何修改文件权限和所有者？chmod 777 是什么意思？**

**【一句话总结】** chmod 改权限(r4w2x1)、chown 改所有者，777 是所有人可读写执行。

**L14. 如何测试网络连通性、排查网络问题？**

**【一句话总结】** ping 测连通、telnet 测端口、curl 测接口、nslookup 查DNS、traceroute 看路由。

**L15. 场景：接口调不通，如何用 Linux 命令排查？**
1. `ping ip` 看服务器是否可达。
2. `telnet ip port` 看端口是否开放/服务是否启动。
3. `curl -v url` 看具体请求响应、状态码。
4. `netstat -anp | grep port` 看服务是否监听端口。
5. `tail -f app.log` 看服务端日志报错。
6. 检查防火墙(`iptables`/安全组)。
**【一句话总结】** 从 ping 通不通、telnet 端口开不开、curl 看响应、日志查报错、防火墙五步逐层排查。

**L17. 如何压缩和解压文件？**

```bash
unzip a.zip                # 解压 zip
```
记忆：c=create打包、x=extract解压、z=gzip、v=显示过程、f=文件名。
**【一句话总结】** tar -zcvf 打包压缩、-zxvf 解压，zip/unzip 处理 zip，c打包x解压z压缩。

**L18. 如何实时监控日志并过滤关键字？**
```bash
tail -f app.log | grep -i "error"       # 实时看错误
tail -f app.log | grep --line-buffered "500"
```
测试排查线上问题最常用组合。
**【一句话总结】** tail -f 实时输出日志，管道接 grep 过滤关键字，实时监控错误。

**L19. 如何查看和设置环境变量？**
```bash
env               # 查看所有环境变量
echo $PATH        # 查看某个变量
export KEY=value  # 临时设置
# 永久设置：写入 ~/.bashrc 或 /etc/profile 后 source 生效
```
**【一句话总结】** env 看全部、echo $VAR 看单个、export 临时设置，写入 .bashrc 永久生效。

**L20. 场景：服务突然响应变慢，如何用 Linux 定位？**
1. `top` 看 CPU、内存、负载(load average)是否过高。
2. `free -h` 看内存是否耗尽、是否在用 swap。
3. `df -h` 看磁盘是否满。
4. `iostat`/`iotop` 看磁盘 I/O 是否瓶颈。
5. `netstat`/`ss` 看连接数是否异常。
6. `top` 定位到高占用进程后，用 `jstack`(Java) 看线程栈。
7. `tail -f` 看应用日志有无异常/GC 频繁。
**【一句话总结】** 从 top 看负载、free 看内存、df 看磁盘、iostat 看I/O、netstat 看连接、日志看异常逐项排查。

## 十一、网络与计算机基础

**N1. TCP 三次握手、四次挥手？为什么握手三次、挥手四次？**
- 三次握手：SYN → SYN+ACK → ACK，建立连接，确保双方收发能力都正常。
- 四次挥手：FIN → ACK → FIN → ACK，断开连接。
- 挥手比握手多一次：服务端收到客户端 FIN 后可能还有数据要发送，因此 ACK 和自己的 FIN 分两次发，故为四次。
**【一句话总结】** 三次握手建连确认双方收发正常，四次挥手断连因服务端要先回ACK再发自己FIN所以多一次。

**N2. TCP 和 UDP 的区别？**
- TCP：面向连接、可靠、有序、有流量与拥塞控制，开销大速度较慢，用于文件传输、网页、邮件。
- UDP：无连接、不可靠、速度快、开销小，用于视频直播、在线游戏、DNS。
**【一句话总结】** TCP面向连接可靠但慢适合传文件网页，UDP无连接不可靠但快适合直播游戏DNS。

**N3. 从浏览器输入 URL 到页面展示，发生了什么？**
DNS 解析域名得到 IP → 建立 TCP 连接（三次握手）→（HTTPS 则进行 TLS 握手）→ 发送 HTTP 请求 → 服务器处理并返回响应 → 浏览器解析 HTML/CSS/JS 渲染页面 → 断开连接（四次挥手）。
**【一句话总结】** DNS解析→TCP握手→(TLS)→发HTTP请求→服务器响应→浏览器渲染→断开连接，是经典全流程题。

**N4. HTTP 常见状态码？**
200 成功、301/302 重定向、304 未修改（用缓存）、400 参数错误、401 未认证、403 无权限、404 未找到、500 服务器错误、502 网关错误、503 服务不可用、504 网关超时。
**【一句话总结】** 2xx成功、3xx重定向、4xx客户端错、5xx服务端错，重点记400/401/403/404/500/502/504。

**N5. 进程和线程的区别？**
- 进程：资源分配的最小单位，有独立内存空间，开销大，进程间通信复杂。
- 线程：CPU 调度的最小单位，同进程内线程共享内存，开销小、通信方便，但一个线程崩溃可能拖垮整个进程。
**【一句话总结】** 进程是资源分配单位有独立内存开销大，线程是调度单位共享内存开销小但一崩全崩。

**N6. HTTP 和 HTTPS 的区别？**
HTTP 明文传输、默认 80 端口、不安全；HTTPS 在 HTTP 基础上加 SSL/TLS 加密、默认 443 端口，通过加密传输、证书验证身份、完整性校验，防窃听、防篡改、防冒充。
**【一句话总结】** HTTP明文80端口不安全，HTTPS加SSL/TLS走443端口，加密+证书+校验防窃听篡改冒充。

## 十二、场景与开放题

**S1. 给你一个杯子，如何测试？（万能发散题）**
- 功能：能否装水、是否漏水、容量准确、把手牢固。
- 界面：外观、颜色、材质、做工。
- 性能：装开水/冰水、承重、抗摔、耐高温。
- 安全：材质无毒、边缘不割手、高温不烫手。
- 兼容：装水/牛奶/酒/咖啡/碳酸饮料。
- 易用性：手感、重量、防滑、清洗方便。
**【一句话总结】** 从功能、界面、性能、安全、兼容、易用性六个维度发散，展示系统化测试思维。

**S2. 如何测试电梯？**
- 功能：上下行、楼层按钮、开关门、报警、超载提示。
- 性能：运行速度、最大载重、频繁使用。
- 安全（重点）：超载保护、断电应急、门夹人保护、急停。
- 异常：多人同时按不同楼层、运行中急停、断电、超载。
**【一句话总结】** 从功能、性能、安全、异常四维度测，重点是超载、夹人、断电等安全保护。

**S3. 如何测试抢红包/秒杀功能？**
- 功能：金额正确、总金额守恒、每人限领次数。
- 并发（重点）：高并发同时抢，验证不超发、不少发、无重复领取。
- 边界：抢完提示、剩最后一个、金额精度到分。
- 异常：网络中断重试是否重复领取、超时未领的回退。
- 性能：瞬时高并发下响应和成功率。
- 安全：接口防刷、防重放、越权抢他人红包。
**【一句话总结】** 重点测高并发下不超发不重复领、金额守恒、防刷防重放，兼顾边界异常和性能。

**S4. 项目上线后出现线上 Bug 怎么处理？**
先评估影响面和严重程度 → 紧急止损（回滚/热修/降级）→ 保留现场（日志、数据）→ 定位根因 → 修复并验证 → 复盘（为什么漏测、如何补用例避免复发）。
**【一句话总结】** 先评估影响止损（回滚热修），再定位根因修复验证，最后复盘补用例防复发。

**S5. 时间紧任务重，如何保证测试质量？**
基于风险优先级排序，优先保障核心主流程和高风险模块；用探索性测试补充；复用自动化回归；与团队明确沟通取舍和风险，把未覆盖点显式上报；必要时争取资源或延期，不隐瞒风险。
**【一句话总结】** 按风险排优先级先保核心流程，用探索性测试和自动化补位，把取舍和风险透明上报。

**S6. 你和开发/产品有分歧时怎么处理？**
基于事实和数据沟通（需求文档、复现证据），对事不对人；先理解对方立场；无法达成一致时升级到负责人或产品决策并记录结论；始终以项目质量和用户体验为共同目标。
**【一句话总结】** 用需求文档和证据对事不对人沟通，谈不拢就升级决策并记录，以质量为共同目标。

**S7. 你认为优秀的测试开发工程师应具备哪些能力？**
扎实的测试理论与用例设计能力、较强的编码能力（Python/Java）、自动化框架与平台开发能力、熟悉数据库/Linux/网络/协议、良好的分析定位与沟通能力、强质量意识与责任心、持续学习能力。
**【一句话总结】** 测试功底+编码能力+框架平台开发+计算机基础+沟通定位+质量意识，编码是测开核心区分点。

**S8. 你平时如何学习和提升？**
关注技术社区/博客/公众号、精读官方文档、动手做项目实践、阅读优秀开源框架源码、参与并做技术分享、复盘项目问题沉淀经验、坚持刷算法题。
**【一句话总结】** 靠文档社区输入、项目和源码实践、技术分享输出、问题复盘沉淀和刷题持续提升。
